Platform Preferences

Platform Preferences holds the settings that fit NeuralSeek to the systems around it: how long a request may take before your chatbot gives up, how much of a conversation is carried into the next question, which language answers come back in, what a filtered search does when it finds nothing, how long a mAIstro agent may run, and which agents run on save or after every answer. Some of them change what an answer says or where it comes from — Cross Language, the output language, filter relaxation, stopwords and HTML cleansing — while the rest fit NeuralSeek to the platforms it serves. The values in the screenshots are one instance’s settings, not product defaults.

Where to find it

Section titled “Where to find it”

Open Neural Config, select the Default Config / Answer Generation node in the routing tree, then select Edit Configuration. In the Configuration: Default Config dialog, expand Platform Preferences. Because the section sits in the Default Config, its settings apply to the whole instance.

Change the settings you need, then select Save and name the version, or select Propose Changes to keep the edit for review. Both are described on Save or propose a change.

Settings

Section titled “Settings”

Timeout and conversation length

Section titled “Timeout and conversation length”

These four settings are sliders with a number box beside them: drag the slider or type a value. The numbers at each end of the track are the range.

Timeout is the language generation timeout, in milliseconds, from 4000 to 90000. Set it a few seconds below the timeout of your chatbot platform. When the timeout is reached, NeuralSeek tries to serve the closest cached answer, if one is available, instead of failing — so NeuralSeek has to give up before your platform does for that fallback to reach the user. How cached answers are kept is on Caching. Raise it when long answers or a slow LLM are cut off and your platform allows the extra time; lower it when your platform’s own limit is shorter.

Context Turns sets the maximum number of previous turns of the conversation fed to the LLM, from 0 to 50. Increasing it is not recommended, for two reasons: every earlier turn takes LLM context away from your documentation, and a longer history gives users more room to steer the model toward inappropriate responses. If follow-up questions lose their subject, try Force carry context before raising this number.

Context Timeout - Session is the timeout of a user session identified by a session_id, from 0 to 999999. Context Timeout - User Only is the timeout of a user-based session that carries no session_id, with the same range. The two are set separately, so you can keep session-based and user-only conversations for different lengths of time. Within the timeout, a new question from the same session or user continues the earlier conversation; once it passes, the next question starts fresh, with no earlier turns carried in. Lengthen a timeout when users come back to a conversation after a pause and expect it to pick up where it left off; shorten it when a later, unrelated question is being read as a follow-up to an old one. How a Seek request ties its turns to a session or a user is on Conversational context.

Context detection

Section titled “Context detection”

Context detection decides how NeuralSeek recognises the language context it carries from one question to the next: with its own fast model, or with an LLM-based mAIstro flow that does custom part-of-speech tagging.

Detection Method has three options:

OptionWhat it does
Model OnlyUses NeuralSeek’s fast built-in model alone.
Model + mAIstro fallbackUses the built-in model, with the agent in mAIstro flow as a fallback.
mAIstro OnlyUses the agent selected in mAIstro flow in place of the built-in model.

mAIstro flow selects the agent that does the tagging: Disabled, or one of your mAIstro agents. It is greyed out while Detection Method is Model Only. Choose a mAIstro method when you need custom tagging that the built-in model does not give you. Each question that uses the flow then runs an LLM-based agent, where the built-in model is the fast path.

Force carry context

Section titled “Force carry context”

Force carry context handles questions with no subject. Set it to True and a question in which NeuralSeek finds no subject or nouns — “and the second one?”, “why?” — is treated as a follow-on to the previous question. Set it to False and such a question is answered on its own. Turn it on when users of your channel tend to ask short follow-ups.

Cross Language

Section titled “Cross Language”

Cross Language (True or False) translates into the knowledge base language when it differs from the language of the Seek. Turn it on when your users ask in a language your knowledge base is not written in. Semantic Scoring is not possible on cross-language response generation, so turning this on disables Semantic Scoring automatically for those answers. How Cross Language works with the knowledge base language and the other language settings is on Language handling.

Relax Filters

Section titled “Relax Filters”

Relax Filters decides what happens when a filtered search finds no documents. Turned on, NeuralSeek relaxes the filter and tries again, so the user gets an answer from the wider knowledge base instead of none. Turned off, the filter always holds. The filter itself is set up on KnowledgeBase Connection, and passing a filter with a Seek request is described on Dynamic filters.

Must Keep Keys (filters to never remove) separated by comma lists the filter keys that are never removed when the filter is relaxed, separated by commas.

Put any filter that controls what a user may see, rather than what is most relevant, in this list: without it, relaxing an empty result could widen access.

mAIstro Stream Plan and mAIstro Max Run Time

Section titled “mAIstro Stream Plan and mAIstro Max Run Time”

mAIstro Stream Plan controls whether the agent plan is streamed while a mAIstro agent runs. Set it to True to stream the plan, or False to keep it back.

mAIstro Max Run Time stops an agent run, including the agents it calls, after this many hours, from 1 to 24. The limit cannot exceed 24 hours. Lower it to stop a runaway or looping agent sooner; raise it for long batch agents that legitimately run for hours.

Log Alternate Configs

Section titled “Log Alternate Configs”

Log Alternate Configs decides whether answers from a Seek called with a proposal or an override of the configuration are logged to the Curate tab. Those calls test a configuration you have not adopted. Keep logging on to review the test answers next to real ones; turn it off when test traffic would crowd the curation list. Proposals are described on Backup, restore & change logs.

Hide API Keys

Section titled “Hide API Keys”

Hide API Keys hides the API keys of connected platforms from configuration admins. Without it, API keys are shown only to users with Admin / Configure permissions. Turn it on when people who edit the configuration should not be able to read the keys.

This setting is one-way

Once Hide API Keys is set to True, it cannot be disabled. From then on, you have to re-enter all API keys whenever you import a configuration file. Decide before you save.

Default Language

Section titled “Default Language”

Default Language sets the default platform language through Default Output Language. The list starts with Match Input, followed by languages listed by name. The default can be overridden for a single request on the Seek tab or in the API by setting the language option.

Choose Match Input to answer in the language of the question; choose a language to answer in that language whatever the question’s language. How the output language works with the knowledge base language and translation is on Language handling.

Virtual Agent Type

Section titled “Virtual Agent Type”

Virtual Agent Type is the format the Curate tab writes when it auto-builds a virtual agent. Choose the one your chatbot platform imports; the export steps for each format are on Training virtual agents.

OptionWrites for
Watson Assistant ActionsWatson Assistant, as actions
AWS Lex V2Amazon Lex V2
Kore.aiKore.ai
CognigyCognigy
Watson Assistant DialogWatson Assistant, as a dialog
Azure Knowledge BaseAn Azure knowledge base
None / Webpage HTMLNo virtual agent platform: a web page, as HTML

Two switches under the selector, each set with Disable or Enable, control links in the responses:

  • Embed links into returned responses for Virtual Agent Types that support it. — embeds links in the responses returned to the virtual agent, on the types that support it.

  • Only show unique embedded links — shows each embedded link once in a response. It matters only when links are embedded.

Stopwords

Section titled “Stopwords”

Stopwords are the common, insignificant words removed during pre-processing. Stopwords replaces NeuralSeek’s default stopword list with your own. Type the words separated by commas — for example a, and, the. Use it only when you want to override the default stopwords, for example when a word on the default list carries meaning in your domain and must not be dropped; otherwise leave it empty. Your list replaces the default rather than adding to it, so include every default stopword you still want ignored.

HTML Cleansing

Section titled “HTML Cleansing”

HTML Cleansing cleanses scraped HTML pages automatically in the knowledge base types that support it, stripping page clutter before the content is used.

  • Enable the automatic HTML Cleanser — True cleanses scraped pages automatically; False keeps them as scraped.
  • Provide an array of CSS selectors to remove from the HTML — extra elements to strip, written as an array of selectors, such as ['.mybadclass']. Add the cookie banners, navigation rails or footers that the automatic cleanser leaves in. [] removes nothing extra.

Save Agents

Section titled “Save Agents”

Save Agents triggers a mAIstro agent whenever something is saved. Each selector offers Disabled or one of your mAIstro agents.

  • Configuration Save Agent — runs when the configuration is saved.
  • mAIstro Save Agent — runs when a mAIstro agent is saved.

Use them for work that should follow a save, for example sending a notification or recording the change in an external log. See also Pipeline hooks.

Post-Seek Agent

Section titled “Post-Seek Agent”

Post-Seek Agent triggers a mAIstro agent asynchronously after each Seek response, so it does not affect Seek latency. Use it to save conversations, log custom analytics or run any other post-processing workflow. Choose the agent in Post-Seek mAIstro Agent; Disabled runs nothing.

The agent receives the full Seek context in the postSeekAgentIn variables: question, answer, answerId, sessionId, user, score, url, document, langCode, sentiment, semanticScore, params and options.

FAQ

Section titled “FAQ”

My chatbot times out before NeuralSeek answers. What do I set?

Section titled “My chatbot times out before NeuralSeek answers. What do I set?”

Set Timeout a few seconds below your chatbot platform’s timeout. NeuralSeek then stops first and tries to serve the closest cached answer, if one is available, instead of leaving your platform to fail the request.

Can I turn Hide API Keys off again?

Section titled “Can I turn Hide API Keys off again?”

No. Once Hide API Keys is set to True it cannot be disabled, and you have to re-enter all API keys when you import a configuration file afterwards.

Why did semantic scores disappear after I turned on Cross Language?

Section titled “Why did semantic scores disappear after I turned on Cross Language?”

Semantic Scoring is not possible on cross-language response generation, so turning on Cross Language disables it automatically for those answers.

How long can a mAIstro agent run?

Section titled “How long can a mAIstro agent run?”

Up to 24 hours. mAIstro Max Run Time sets the limit, from 1 to 24 hours, and stops the run together with the agents it calls.

How do I run something after every answer without slowing Seek down?

Section titled “How do I run something after every answer without slowing Seek down?”

Choose an agent in Post-Seek mAIstro Agent. It runs asynchronously after each Seek response and receives the Seek context through the postSeekAgentIn variables.
