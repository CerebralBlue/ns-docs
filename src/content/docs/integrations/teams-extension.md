## What is it

The Teams Extension is the screen under **API's & Integration** → **Teams Extension** titled **Integrating with Microsoft Teams**. It connects a Microsoft Teams workspace to NeuralSeek, so people can ask questions of your knowledge base from a personal chat with a bot or by @mentioning the bot in a channel.

The connection runs through an **Azure Bot** that you create in your own Azure tenant. NeuralSeek gives you the URL the bot sends Teams messages to, stores the bot's credentials, and generates the Teams app package you install. In the screen's own words, the integration lets "team members to query, analyze, and share insights directly in Teams" and can "optionally route events to specialized agents for custom behaviors".

## Why it matters

Most questions get asked where people already work. With the bot in Teams, a user does not have to open a separate tool to get an answer from NeuralSeek — they message the bot, or @mention it in the channel where the conversation is already happening, and the answer comes back in Teams.

The screen walks you through the whole setup in seven numbered steps, and generates the two NeuralSeek-specific pieces for you — the messaging endpoint and the app package — so the only values you create yourself are the Azure Bot's App ID and Client Secret.

## When to use it

Use the Teams Extension when your organization works in Microsoft Teams and you want NeuralSeek answers available there, either to everyone (deployed through the Teams Admin Center) or to a few testers first (sideloaded).

It is the wrong tool when:

- Your team works in Slack — use the [Slack extension](/integrations/slack-extension/) instead.
- You are building your own chat front end or calling NeuralSeek from an application — call the [REST API](/integrations/rest-and-console-api/) directly.
- You cannot create an Azure Bot resource in your Azure tenant. The bot is required; there is no Teams connection without it.

## How it works

The screen is a numbered setup guide, followed by two collapsed sections — **Teams Credentials** and **Additional Settings** — and a **Save** button at the bottom right.

![The Teams Extension screen, Integrating with Microsoft Teams: steps Create an Azure Bot (with the Azure Portal link), Get App Credentials, Configure Messaging Endpoint with the endpoint box, Enable Teams Channel, and Download & Deploy App Package with the Download App Package button; Save at the bottom right](/img/admin-tools/teams-extension.png)

### Create the Azure Bot (steps 1–4)

Steps 1 to 4 happen in Azure. They create the bot, give you its credentials and point it at NeuralSeek.

1. **Create an Azure Bot** — go to the **Azure Portal** (the link opens portal.azure.com) and create a new Azure Bot resource. Select "Single Tenant" for the app type and create a new Microsoft App ID. Once it is created, note the **Microsoft App ID** shown on the bot's Configuration page.
2. **Get App Credentials** — on the same Configuration page, click **Manage Password** next to the App ID and create a new **Client Secret**. Copy it straight away: Azure shows it only once. The App ID and the Client Secret are the Azure Bot credentials NeuralSeek needs; you enter them under **Teams Credentials** (next section) and click **Save**.
3. **Configure Messaging Endpoint** — in the Azure Bot's Configuration, set **Messaging endpoint** to the URL the screen shows in its code box. It has this form:

   ```text
   https://<your console host>/v1/teams/messages/<your instance id>
   ```

   The URL is specific to your NeuralSeek instance, so copy it from the screen with the **Copy to clipboard** button rather than typing it. This is the address Teams messages are delivered to.

4. **Enable Teams Channel** — in the Azure Bot, go to **Channels** and add **Microsoft Teams**. Accept the terms of service and click **Apply**.

### Teams Credentials and Save

**Teams Credentials** is a collapsed section below the setup steps. Expand it and enter the two values from step 2: the **App ID** and the **Client Secret**. Then click **Save** at the bottom right of the screen. Saving stores the credentials in NeuralSeek; the app package in step 5 is meant to be downloaded only after this save.

The screen asks for a Single Tenant bot in step 1.

### Download App Package and deploy it (step 5)

Step 5, **Download & Deploy App Package**, is where NeuralSeek hands you the Teams app. After saving your credentials, click **Download App Package** to download the auto-generated Teams app package — a zip file. You then install that zip in Teams in one of two ways.

**Option A: Deploy for your organization** — for a rollout to your users, through the Teams Admin Center.

1. Go to the **Teams Admin Center** (the link opens admin.teams.microsoft.com).
2. Navigate to **Teams apps** > **Manage apps**.
3. Click **Upload new app** and select the downloaded zip.
4. Configure app policies under **Setup policies** to control who has access to the bot.

**Option B: Sideload for testing** — for trying the bot yourself before a wider rollout.

1. Open Microsoft Teams.
2. Click **Apps** in the left sidebar.
3. Click **Manage your apps** at the bottom.
4. Click **Upload an app** > **Upload a custom app**.
5. Select the downloaded zip file.

### Test the Integration and Additional Settings (steps 6–7)

**Test the Integration** (step 6): find your bot in Teams by searching for it in the **Apps** section. Start a personal chat with it, or @mention it in a channel, and check that NeuralSeek responds. If it does not, go back over the earlier steps: the **Messaging endpoint** in Azure should match the URL on the screen, the Microsoft Teams channel should be added to the bot, and the App ID and Client Secret should be saved in **Teams Credentials**.

**(Optional) Additional Settings** (step 7): the screen suggests reviewing "other settings like streaming responses and reply behavior in channels". They sit in the collapsed **Additional Settings** section, which holds two settings:

<!-- UNCONFIRMED: what Streaming Responses and Reply to all messages in channels do — read from their labels and from step 6 ("@mention it in a channel"); the expanded Additional Settings section, its control types and help text are not on any screen documented here -->

- **Streaming Responses** — sends the answer into Teams progressively as it is generated, instead of as one message once it is complete. Turn it on when answers are long and users would otherwise wait with nothing on screen.
- **Reply to all messages in channels** — makes the bot answer every message posted in a channel it is in, not only messages that @mention it. Leave it off in busy channels, where the bot would otherwise reply to conversations that were not meant for it.

You can also set a welcome message for the bot on this screen — the text a user sees when they first open the bot in Teams.

## FAQ

**What do I set as the bot's messaging endpoint?**
The URL shown in step 3, **Configure Messaging Endpoint**, of the form `https://<your console host>/v1/teams/messages/<your instance id>`. Copy it with **Copy to clipboard** and paste it into the Azure Bot's **Messaging endpoint** field.

**Where do I enter the App ID and Client Secret?**
In the **Teams Credentials** section of the Teams Extension screen, below the setup steps. Click **Save** afterwards — the app package is meant to be downloaded only after the credentials are saved.

**Which app type should I pick when I create the Azure Bot?**
"Single Tenant", as step 1 on the screen says, and then create a new Microsoft App ID for it.

**How do I install the bot for everyone in my organization?**
Click **Download App Package**, then in the **Teams Admin Center** go to **Teams apps** > **Manage apps**, click **Upload new app**, select the zip, and control access with **Setup policies**.

**Can I try the bot without deploying it to the whole organization?**
Yes, sideload it (Option B in step 5). In Teams, click **Apps** > **Manage your apps** > **Upload an app** > **Upload a custom app** and select the downloaded zip.

**Why doesn't the bot answer every message in a channel?**
In a channel you @mention the bot to get an answer. **Additional Settings** has a **Reply to all messages in channels** setting for making the bot respond to every channel message.
